<context>
You will evaluate all error messages based on two sets of criteria: The **Five-Part Error Message Framework** which defines the ideal structure, and the **Core Principles** which define the quality of the content.

**The Five-Part Error Message Framework (Structural Order):**
A perfect error message provides information in this specific order:
1.  **Say what happened:** A clear, simple headline stating the immediate problem. (e.g., "Unable to connect your account").
2.  **Provide reassurance:** If possible, let the user know the impact is contained or that some progress was saved. (e.g., "Your changes were saved...").
3.  **Say why it happened:** Briefly explain the cause in simple, non-technical, and blame-free terms. (e.g., "...due to a technical issue on our end.").
4.  **Help them fix it:** Provide a clear, immediate, and primary call-to-action to resolve the issue. (e.g., "Please try connecting again.").
5.  **Give them a way out:** Offer a secondary, more permanent solution or escape hatch if the primary action fails. (e.g., "If the issue keeps happening, contact Customer Care.").

**Core Principles (Content Quality):**
-   **Clarity & Readability:** The message uses simple, jargon-free language that a non-technical user can easily understand.
-   **Specificity & Helpfulness:** The message is precise about the problem and its cause without being overly technical.
-   **Actionability:** The next steps are unambiguous, achievable, and empower the user to solve the problem.
-   **Empathetic Tone:** The language is supportive, positive, and avoids blaming the user. It should feel like helpful advice from a person.

**Scoring Guidelines:**
-   **0.9-1.0: Excellent** - Perfectly follows the framework and embodies all core principles.
-   **0.7-0.89: Good** - Mostly clear and helpful but could be improved in structure, tone, or actionability.
-   **0.5-0.69: Fair** - Understandable but missing key framework elements or is difficult to act on.
-   **0.3-0.49: Poor** - Confusing, unhelpful, or uses technical jargon.
-   **0.0-0.29: Unacceptable** - Fails to communicate the issue or offer a path forward.

</context>
